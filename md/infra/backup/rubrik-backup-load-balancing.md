# Rubrikのバックアップ負荷分散ガイド！リソース制限ができない時の対策

## 超要約
[Rubrik](https://fununi222.github.io/website/html/glossary/system-glossary.html#:~:text="Rubrik") (Rubrik Security Cloud) 導入時、「バックアップ実行中に本番ストレージのI/O負荷が急増する」「Rubrik側でバックアップ受信帯域のスロットリングが設定できない」という課題が散見されます。本稿では、Rubrikのデータ取得思想とIngress/Egress制御の差分、および本番ストレージの過負荷（Noisy Neighbor問題）を防ぐ4つのロードバランシング・ベストプラクティスを解説します。

---

## 1. なぜRubrikはバックアップ時の帯域スロットリング（Ingress）を直接制御できないのか？

Rubrikにおけるデータトラフィックの帯域制御は、通信の方向によって挙動が明確に分離されています。

- **バックアップ時（Ingress: 本番 ➔ Rubrik）**: 直接的な帯域固定キャップ機能は非搭載。最短時間でデータを保護するアーキテクチャ思想。
- **アーカイブ・レプリケーション時（Egress: Rubrik ➔ クラウド/二次サイト）**: 時間帯別スロットリングやネットワーク帯域キャップを細かく制御可能。

Rubrikはバックアップ時に受動側となるため、受信側から送信元（本番ストレージ/VMware ESXi）の読み出しトラフィックを直接物理抑止することができません。そのため、フラッシュストレージ環境では全開でデータ転送が行われ、I/Oの競合が発生することがあります。

---

## 2. 本番ストレージ過負荷を防ぐ4つの最適化策

### 1. OSレベルでのQoS・帯域幅制御（Physical Agent）
Windows Server (QoS Policy) や RHEL (tc/cgroups) 上でRubrik Backup Service (RBS) 通信にアウトバウンド上限を設定。

### 2. VMware vDS（分散仮想スイッチ）でのトラフィックシェーピング
VMware vSphere環境において、バックアップ用 vmkernel ポートが所属する PortGroup / vDS で平均帯域幅・ピーク帯域幅を制御。

### 3. Rubrikマルチセクション・並列ストリーム数の調整
Rubrik SLA設定画面の「詳細設定」より、並列読み出しチャネル数（Parallel Channels）を制限し、間接的にストレージI/Oを低下。

### 4. ストレージアレイ・ネイティブスナップショット連携（SAN Direct/Array Integration）
ハイパーバイザー（ESXi）経由のデータ読み出しを避け、ストレージアレイ（Pure, NetApp, Dell等）の物理スナップショットと連携してI/Oをストレージアレイへオフロード。

---

## 3. タスク同時実行数（Concurrency Limits）の隠れた仕様

Rubrikクラスタは各ノードの安定稼働のため、デフォルトで同時実行タスク数にハードリミットが設定されています（例: 1 ESXiホストあたり最大3タスク、1 Rubrikノードあたり最大3タスク）。大規模環境でキュー待ちが発生する場合は、Rubrikサポートを介してバックエンドパラメーターの最適化を行います。

---

## 4. 結論：負荷分散のために「クラスタを追加・分割」すべきか？

負荷を分離するために「小規模クラスタを個別に増設する」手法は、重複排除効率を低下させ運用管理を煩雑にする**アンチパターン**です。
